# Qualification campaign registration

Before measurement: the gate, pins, four arms, 11 functions, frozen five-case corpus and three production LOD-chain meshes, median of three, and exact-proof requirements are those in SPEC-0216-qualify. Regression is any candidate/base case >1.01; per-function SHIPS requires real-mesh geometric mean <=0.97 and complete exact proof. Optimesh has no cluster LOD. Measurement is instructions:u only, using the peers allocation and input policy. This registration does not narrow the required proof domain.

The original peers adapter lacked update, prune and points. Its first attempt stopped at tiny-smooth/update with exit 1, after 69 accepted samples. The continuation retains those samples and their original binding, builds a second four-arm adapter with the missing operations, and skips all completed keys. Each complete case has all three repetitions from the same adapter; both bindings and the failed attempt are retained. The update workload uses positions only, prune uses error 0.5, and points uses half the vertices without colors, matching the registered peers-derived workloads. Update serialization includes the indices, error and all position bytes.
The continuation's first base build exited 101 because the update adapter used the wrong result field; that pre-measurement build and binding are retained. The corrected adapter emits serialization outside the counted region, as the peer consumer does.
